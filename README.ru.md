Строка состояния для [Command Code](https://commandcode.ai) (`cmd`, в Windows — `cmdc`): модель,
полоса контекста с градиентом, доля попаданий в кэш, стоимость сессии, скорость вывода, расход
субагентов, имя сессии и состояние git — всё в строке под полем ввода.

```text
deepseek-v4.1-flash │ max │ █░░░░░░░░░░░ 32k (3.2%) │ cache 99% │ $0.013 │ 42 tok/s │ sub 16k │ Simple Reply │ main ↑1 │ +1 ~2 ?1 │ my-project
```

В Command Code нет внешнего хука `statusLine`, как в Claude Code: `cmd.ui.setStatus()` (API модов) —
единственный способ нарисовать постоянную строку под полем ввода, и этот мод использует именно его.

## Требования

**Command Code ≥ 1.10.0** (`cmd`, под Windows — `cmdc`). Старые версии **не поддерживаются**: при
обнаружении старого хоста мод не делает вообще ничего — ничего не регистрирует, не рисует строку и
оставляет в ленте одно уведомление об обновлении, после чего отключается. Выполните `cmdc update`
и откройте сессию заново. Нижняя граница не выдумана: до 1.10.0 в API модов нет
`cmd.ui.capabilities` (сверено со всеми опубликованными пакетами 1.x), поэтому мод даже не может
понять, рисует ли этот хост строку — он бы падал с исключением, а не деградировал. В отчёте
`/statusline` видна определённая версия хоста.

## Установка

```bash
cmd mods add cmdc-statusline -g              # из npm (-g = область пользователя; без -g — только текущий проект)
cmd mods list                                # мод должен появиться в списке
```

Тот же пакет ставится и прямо из git: `cmd mods add holtwood/cmdc-statusline -g`, если не хочется
зависеть от реестра.

Можно и просто положить файл, без пакетного менеджера: `index.ts` в
`~/.commandcode/mods/statusline.ts` (`%USERPROFILE%\.commandcode\mods\statusline.ts` в Windows),
затем новая сессия:

```bash
mkdir -p ~/.commandcode/mods && curl -o ~/.commandcode/mods/statusline.ts \
  https://raw.githubusercontent.com/holtwood/cmdc-statusline/main/index.ts
```

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.commandcode\mods" | Out-Null
Invoke-WebRequest -OutFile "$env:USERPROFILE\.commandcode\mods\statusline.ts" `
  https://raw.githubusercontent.com/holtwood/cmdc-statusline/main/index.ts
```

Выберите один способ установки: пакет и вручную положенный файл — это два разных мода, объявляющих
одни и те же имена флагов, а Command Code разрешает имена флагов глобально между модами.

> В Windows бинарник называется `cmdc` (`cmd` открывает оболочку Windows) — используйте `cmdc mods add …`, `cmdc mods list`, `cmdc --mod .\index.ts`.

Попробовать без установки: `cmd --mod ./index.ts`. Моды загружаются один раз на процесс — после
правок нужен `/reload` или новая сессия. Шага сборки нет: Command Code компилирует TypeScript
при загрузке.

### Установка силами ИИ-агента

Если не хочется трогать оболочку, вставьте это своему агенту (Claude Code, Codex, Command Code и т. п.):

> Установи мод Command Code `cmdc-statusline` в области пользователя: выполни
> `cmd mods add cmdc-statusline -g` (в Windows используй `cmdc` вместо `cmd`; если npm не находит
> пакет, возьми `holtwood/cmdc-statusline`), затем подтверди через `cmd mods list`, что
> `cmdc-statusline` виден как пользовательский мод и без предупреждений о загрузке. В конце
> напомни мне перезапустить сессию, чтобы строка отрисовалась.

Права root не нужны: запись идёт только в `~/.commandcode/mods/` и в ключ `mods.sources`
файла `~/.commandcode/settings.json`.

## Сегменты

| Сегмент | Значение |
|---|---|
| `deepseek-v4.1-flash` | Текущая модель, ровно как сообщил запрос (`raw-model=true` сохраняет префикс провайдера) |
| `max` | Уровень рассуждений последнего запроса |
| `█░░░ 32k (3.2%)` | Контекст последнего запроса: полоса с градиентом (зелёный→жёлтый→красный по ячейкам), токены, доля окна |
| `cache 99%` | Доля попаданий в кэш промпта (чтения кэша ÷ вход) |
| `$0.013` | Стоимость сессии: история при возобновлении + новое в этом процессе |
| `42 tok/s` | Скорость вывода последнего запроса (по настенным часам, включает ожидание первого токена) |
| `sub 16k` | Токены, израсходованные субагентами (инструмент `agent`) за сессию |
| `Simple Reply` | Имя сессии (сохраняется после `/reload` и возобновления) |
| `main ↑1` | Ветка git с ahead/behind |
| `+1 ~2 ?1` | в индексе · изменено · не отслеживается (`clean`, если чисто) |
| `my-project` | Имя текущего каталога |

## Настройка

Настройки хранятся в JSON; командная строка может переопределить их на один запуск.

```
~/.commandcode/statusline.json          область пользователя
<проект>/.commandcode/statusline.json   область проекта (приоритетнее)
--mod-option <name>=<value>             разовое переопределение
```

```json
{
	"bar-width": 12,
	"cache": true,
	"cost": true,
	"speed": true,
	"sub": true,
	"cwd": true,
	"refresh": 10
}
```

`preset` задаёт готовый набор сегментов, чтобы не перечислять десяток ключей:

| `preset` | Включено |
|---|---|
| `full` (по умолчанию) | все |
| `minimal` | `model` `effort` `context` `bar` `percent` `git` |
| `usage` | `context` `bar` `percent` `cache` `cost` `sub` |

Пресет решает только *какие сегменты показывать*. Ключ, написанный рядом, его перекрывает
(`{"preset": "minimal", "cost": true}` сохранит стоимость), а переключатели отрисовки (`ascii`,
`raw-model`) от него не зависят. Неизвестный пресет называется в отчёте и трактуется как `full`.

| Ключ | По умолчанию | Примечание |
|---|---|---|
| `model`, `effort`, `context` | `true` | модель / рассуждения / контекст последнего запроса |
| `bar`, `bar-width`, `percent` | `true`, `12`, `true` | полоса, ширина в ячейках, процент |
| `cache` | `true` | доля попаданий в кэш |
| `cost` | `true` | стоимость сессии |
| `speed` | `true` | скорость вывода |
| `sub` | `true` | токены субагентов |
| `name` | `true` | имя сессии (обрезается до 24 символов) |
| `git` | `true` | ветка + счётчики изменений |
| `cwd` | `true` | имя каталога |
| `preset` | `full` | `full` / `minimal` / `usage` |
| `raw-model` | `false` | сохранять префикс провайдера |
| `ascii` | `false` | принудительный ASCII-рендеринг |
| `refresh` | `10` | секунды между перечитываниями git (0 — таймер выключен) |

### Видеть, что действительно действует

`/statusline` печатает отрисованную строку, исходные значения за ней и таблицу
`ключ / по умолчанию / действует / источник` по всем ключам, плюс прочитанные файлы конфигурации и
по строке на всё, что не удалось использовать: неизвестный ключ (обычно опечатка), значение
неподходящей формы, неизвестный пресет. Отклонённые значения возвращаются к значению по умолчанию и
говорят об этом — вместо того чтобы примениться наполовину и оставить вас гадать, почему правка
ничего не изменила.

### Менять, не редактируя JSON вручную

`/statusline config` делает то же самое через диалоги Command Code (`cmd.ui.select` / `input` /
`confirm`): область (пользовательская или проектная), ключ, значение, подтверждение. Перезаписывается
только этот ключ — остальное содержимое файла, включая незнакомые этому mod ключи, сохраняется, —
затем конфигурация перечитывается и строка **перерисовывается сразу**. Обходной путь через `/reload`
больше не нужен. Запуск без диалогов (headless) печатает отчёт и ничего не пишет; отказ от
подтверждения тоже ничего не пишет. Если что-то с более высоким приоритетом (файл проекта,
`--mod-option`) сохраняет прежнее значение, поток прямо об этом скажет — вместо того чтобы оставить
вас с записью, которая видимо ничего не изменила.

(Собственные сообщения `/statusline` — на китайском.)

**О приоритете:** Command Code стирает **значения** `--mod-option` из argv, который видит мод.
Поэтому флаг считается явным переопределением только если его значение **отличается от встроенного
по умолчанию**. Явная передача значения по умолчанию (`--mod-option cwd=true`) не побеждает файл
настроек.

## Отрисовка

- **При запуске.** Почти все сегменты описывают **последний запрос к модели**, которого у сессии
  без единого запроса ещё нет, — поэтому строка сразу рисует то, что уже известно, а не ждёт
  первого `model_request_end`: модель и effort из `~/.commandcode/config.json`, плюс имя сессии,
  состояние git и каталог. **Возобновлённая** сессия дополнительно восстанавливает из transcript
  модель, effort, контекст, долю попаданий в кэш и стоимость последнего запроса, так что
  открывается той же полной строкой, с которой её закрыли. Запроса действительно требуют только
  скорость вывода и токены субагентов (ни то, ни другое продукт не сохраняет).
- `COLORTERM=truecolor|24bit` → 24-битная градиентная полоса; иначе приближение 256 цветами;
  `ascii=true` или `TERM=dumb` → `#`/`-`; `NO_COLOR` оставляет блочные символы, убирая цвет.
- **Узкий терминал — без обрезки:** сегменты отбрасываются по приоритету
  (`cwd` → скорость → effort → субагенты → кэш → имя сессии → стоимость → изменения, затем контекст
  сжимается с полосы → токены+% → токены, последней уходит ветка) и строка сразу перерисовывается
  при изменении размера. Модель не отбрасывается никогда.

## Откуда берутся числа

| Значение | Источник | Достоверность |
|---|---|---|
| модель / effort / контекст / кэш | события `model_request_start` / `model_request_end` (model/effort до первого запроса — из `~/.commandcode/config.json`, при возобновлении — из transcript) | точно после запроса; начальное значение — из самого продукта |
| стоимость сессии | `costUsd` из `<sessionId>.jsonl` при возобновлении + `usage` каждого запроса по таблице цен | часть при возобновлении — собственное число продукта; новая часть воспроизводит его расчёт (сверено запись за записью) |
| токены субагентов | событие `subagent_stop` | токены точно; расход субагентов **не** входит в стоимость (продукт его тоже не сохраняет) |
| имя сессии | событие `session_titled` + `<sessionId>.meta.json` при старте | по мере возможности — формат файла недокументирован, чтение обёрнуто в `try` |
| ветка / изменения | `git status --porcelain=v1 -b` через `cmd.exec` | точно, кэш 5 с |

Таблицы окна контекста и цен **генерируются** из каталога моделей, поставляемого с CLI, а не
пишутся вручную:

```bash
python3 scripts/gen-model-tables.py           # перегенерировать после обновления CLI
python3 scripts/gen-model-tables.py --check   # упадёт, если таблицы разошлись (это делает CI)
```

Отсутствующая модель деградирует аккуратно: нет окна — нет полосы и процента; нет цены — нет стоимости.

## Разработка

```bash
node test/statusline.test.mjs     # весь набор: без зависимостей и сборки
python3 scripts/gen-model-tables.py --check
```

Тесты импортируют `index.ts` напрямую: Node 22.18+/24 удаляет типы, поэтому инструментарий не нужен.
Проверить другую копию: `STATUSLINE_MOD=/path/to/statusline.ts`. CI прогоняет тот же набор в Linux,
macOS и Windows.

## Известные ограничения

- **Нет сегмента кредитов и квот.** Другие моды читают API Command Code ради остатка кредитов и окон
  5 часов/неделя; этот намеренно локальный (без сети и без `auth.json`).
- Стоимость новых запросов считается по встроенной таблице цен, а не перечитывается из транскрипта,
  поэтому при изменении цен нужно перезапустить `scripts/gen-model-tables.py` (и «семя» возобновления,
  и расчёт по запросу сверены с числами продукта).
- Имя сессии и восстановление стоимости читают `~/.commandcode/projects/**`, а начальные model/effort
  при запуске — `~/.commandcode/config.json`; это недокументированные расположения. Всё обёрнуто так,
  что при изменении раскладки просто исчезает сегмент, а не падает сессия.
- **Опрос в огромных репозиториях.** Строка перечитывает `git status` каждые `refresh` секунд
  (по умолчанию 10). В небольших репозиториях вызов бесплатный, в огромных — нет: увеличьте
  `refresh` или поставьте `0` и положитесь на обновления по событиям.
